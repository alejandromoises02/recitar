# t12: usage analytics in PostHog, per environment (board ticket t12)
Objective: the owner can see in PostHog which filters are used, which shows are opened, how many visits there are and which ticket buttons are clicked, split by dev / test / prod. Branch: `dev`. Delivery: ask-on-risk (no commit without the user's OK, per project CLAUDE.md). Tests: pytest (`server/`), Vitest + `npm run test:a11y` (`client/`).

## Specs
- S1. User, 2026-11-15, verbatim: "quiero incluir el nombre para que sea mas facil de identificar rapido, ademas quiero que se reporte cuando se le da click a comporar entrada, click a ver un evento en particular, quiero reportar los filtros que se usan para poder saber cuales son los fltros mas usados quiero un dashboar para poder saber cuales so los filtros mas usados cuando la gente entra a un show ycuando le dan click air a comporar las entradas ademas tambien quiero repoarta la sesion o sea cuanrtas personas entran a ver, y necesito que este dashboard tenga etpas una para dev una para test una para prod para tenerlos diferenciados"
- S2. The ticket click event carries the show's name (not only its id).
- S3. Events are reported when a visitor: clicks to buy tickets (done, t12 server part), opens a show, uses a filter (which filter, which value), and starts a visit.
- S4. Visits are counted with a random session id the app makes when it starts. It lives only in memory (no cookie, no storage), is never tied to a person, and is the PostHog `distinct_id` of that visit's events, with no person profile and no IP. User: "si" (to the random session id).
- S5. Every event carries `environment` = dev | test | prod, so one dashboard can be filtered per stage.
- S6. A dashboard in PostHog shows most used filters, shows opened, visits and ticket clicks, for each environment.

## Assumptions (not asked yet, change on request)
- A1. Client events reach PostHog through our server (`POST` endpoint + CORS), not a browser SDK: no SDK, no cookies, no autocapture.
- A2. Free-text search: only "search used" is reported, never what was typed.
- A3. Environment split is a property on one PostHog project (the Free plan has 1 project); separate projects need pay-as-you-go.
- A4. Views, filters and visits go only to PostHog (no own table). Ticket clicks keep their own table.
- A5. The dashboard itself is built by the user in PostHog; the assistant lists the events and properties.
- A6. PostHog "Discard client IP data" is switched on by the user in PostHog (the server's IP was visible on events).
