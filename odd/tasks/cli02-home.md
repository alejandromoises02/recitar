# cli02: home in React Native

Objective: build the approved home ("The Night Marquee") in the Expo client, one section at a time, each testable on the user's iPhone (Expo Go) and the Android emulator before the next starts.
Branch: `dev` (one work-unit commit per section, with the user's OK). Delivery: ask-on-risk. Tests: vitest (`npx vitest run` in client/), typecheck `npx tsc --noEmit`, lint `npm run lint`.

## Specs

- S1. Ticket cli02, verbatim: "Construir la home según .impeccable/surfaces/home.md (sección \"Chosen design\") y DESIGN.md, con la maqueta .impeccable/mocks/home/home.html como referencia: marquesina de recién anunciados + abanico de destacados con recuadro; franja Próximos (8); agenda por mes con filtros fecha/lugar; en celular primero el abanico. Un show por fila con +N fechas; skeletons, error con reintento, sin resultados, imagen faltante; bilingüe (voseo + inglés). Depende de des03, api10, api11, api12 y api13. Skills: vercel-react-native-skills, make-interfaces-feel-better, transitions-dev/polish (Reanimated)."
- S2. Split by section so each stage can be tried on devices (user, L2).
- S3. Data comes from the API built in api10-13: `GET /shows` (one item per show, all dates, `name`, `first_seen_at`), `sort=announced&announced_from=<14 days ago>` for Just announced, `GET /featured` (`kind: picked | just_announced`), filters `q`, `from`, `to`, `venue`, `category`. The UI shows `name`, never the raw `title`.
- S4. Visual source of truth: DESIGN.md + `client/src/design/tokens.ts`; motion with Reanimated 4 and the motion tokens; no CSS variables, no hover-only behaviour on touch; respect reduced motion.
- S5. Fonts (Alfa Slab One, Unbounded, Onest, Barlow Condensed) installed as exact-pinned packages at least two weeks old, through the public npm registry (local .npmrc), never the corporate one.
- S6. The user runs Expo, emulators and devices personally; the assistant only gives the steps (memory feedback-user-runs-dev-tooling).
- S7. Spotify sample: official compact embed, visible, with Spotify branding (no hidden player); only for shows with a Spotify match; check play/pause on iOS and Android WebViews before building it.
- S8. Code conventions (user, L7): comments few, in English, only when needed, never quoting Spanish UI copy; each component's styles in a sibling `<Component>.styles.ts`, its own constants in a sibling `<Component>.constants.ts` (shared ones in a shared constants module or tokens.ts), shared style pieces reused from a shared `*.styles.ts`, one component per file. Applies to every component, T1-T3 included. Also in the root CLAUDE.md "Code conventions".

- S9. Accessibility (user, L31: "armemos mas ese ticket con todo lo de ada que puedas cargarle"). Target: WCAG 2.2 level AA on iOS, Android and web, checked by hand with VoiceOver (iOS), TalkBack (Android) and keyboard + a screen reader on web. Every item below needs its check written down in the Log before it is ticked.
  - S9.1 Text alternatives (1.1.1): photos and flyers are decorative because the row or card already says the show (hide them from screen readers); the logo reads "recitAR"; icon-only buttons (arrows, ✕, +, pause) have a spoken label.
  - S9.2 Structure (1.3.1, 2.4.6): one page heading (the headline), section titles as level-2 headings, month / week / day titles as level-3 (role heading + aria-level on web); listings exposed as lists on web.
  - S9.3 Reading and focus order (1.3.2, 2.4.3): screen readers and Tab follow the visual order in both layouts (phones: fan, board, Próximos, explore; wide: board left, fan right); the explore filters come before the results.
  - S9.4 Contrast (1.4.3, 1.4.11): text 4.5:1 (3:1 for large text), including muted text, placeholders and text on the yellow accent; borders and states that carry meaning (chips, day tiles, calendar today ring, focus ring, autoplay bar) 3:1. Extend tokens.test.ts to cover these pairs.
  - S9.5 Text size (1.4.4): works with the system font size at 200% (iOS Dynamic Type, Android font scale, browser zoom): nothing clipped or overlapping; set maxFontSizeMultiplier only where a layout cannot grow (split-flap cells, date blocks) and keep them readable.
  - S9.6 Reflow (1.4.10): web at 320 CSS px wide has no horizontal page scroll; the intended sideways rows (carousel, Próximos, filter rows) stay usable.
  - S9.7 Keyboard (2.1.1, 2.1.2): everything works without a pointer on web: fan previous / next / pause and Left / Right arrows when the fan has focus, ticket button, chips, day tiles, "+", calendar (arrow keys move by day and week, Enter picks, Escape closes), group switch, search. No keyboard trap outside the calendar dialog.
  - S9.8 Visible focus (2.4.7, 2.4.11): a clear focus ring on every focusable element on web, in the accent colour, never hidden under other content.
  - S9.9 Skip link (2.4.1): on web, a first "Saltar a la cartelera" link that moves focus to the explore section.
  - S9.10 Page title and language (2.4.2, 3.1.1): web document title "recitAR"; html lang follows the app language (es / en, with T7).
  - S9.11 Motion (2.2.2, 2.3.3): autoplay can be paused (done) and stops on touch (done); with reduce motion on, no autoplay, no flips, no sleeve or record motion, card text swaps without fades; nothing flashes.
  - S9.12 Gestures (2.5.1, 2.5.7): every swipe or drag has a single-tap alternative (fan arrows: done; Próximos arrows on wide screens: done; phones scroll natively).
  - S9.13 Target size (2.5.8): every control at least 44 x 44 pt (Apple / Android guidance, above the AA minimum of 24): chips, day tiles, calendar cells and ✕ grow or get hitSlop.
  - S9.14 Names, roles, states (4.1.2): pause is a toggle with its pressed state; chips and day tiles report selected; the group switch is a radio group; disabled calendar days say so; the fan announces "carrusel" and the centre show.
  - S9.15 Status messages (4.1.3): the explore result count, "loading more", errors and "no results" are announced without moving focus (aria-live polite on web, AccessibilityInfo.announceForAccessibility on iOS / Android); manual fan moves are announced (done), autoplay is not.
  - S9.16 Dialog focus (calendar): opening moves focus to the dialog title; closing (✕, outside, Escape, picking a day) returns focus to the "+" tile; picking a day announces the new filter.
  - S9.17 Live data: the split-flap rows read as one sentence each (date, name, venue, more dates: done); the autoplay progress bar is hidden from screen readers (done).
  - S9.18 Tooling, each needs the user's OK before installing: @testing-library/react-native (assert labels, roles and states in tests), eslint-plugin-react-native-a11y (lint rules), axe-core with Playwright for automated web checks. Without them, checks are manual and recorded in the Log.
