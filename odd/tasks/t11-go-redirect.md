# t11: /go/<id> redirect that counts ticket clicks (board ticket t11)
Objective: every "Entradas" button goes through our own redirect, which counts the click and adds `utm_source`. Branch: `dev`. Delivery: ask-on-risk. Tests: pytest (`server/`, `RUN_DB_TESTS=1` for the DB ones), Vitest + `npm run test:a11y` (`client/`).

## Specs
- S1. Board ticket t11, verbatim: title "Redirect /go/<id> con registro de clics", note "Agrega utm_source."
- S2. User, 2026-11-15, verbatim: "umm podemos capaz mandar al back y de ahi a la metrica dices que es mejor asi? se me ocurre que es buena idea tener nuestro propio conteo de clciks a shows y a comprar entradas, capaz pdroiamos usarlo para setear lo maas destacado usando esos datos". Agreed design (user: "si"): the server keeps its own count (table in Neon) and later forwards the event to PostHog from the server; the count may later feed "featured".
- S3. `GET /go/{event_id}` answers 302 to a ticket link stored for that event (the one of `?v=<vendor>` when given, else the first, else the show's source page) with `utm_source=recitar`. The destination always comes from the database, never from the request, and is http(s) only.
- S4. Each click is stored with: show id, event (date) id, vendor, where in the app it came from, when. No IP, no user agent, no personal data.
- S5. The redirect never fails because of the count: if storing fails, the visitor is still redirected. Crawlers and link previews are redirected but not counted.
- S6. The app's ticket buttons (show page, pinned bar on phones, home spotlight) point to `/go/<event id>`.
